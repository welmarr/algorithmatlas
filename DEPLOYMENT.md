# Deployment

Build with `pnpm install --frozen-lockfile && pnpm build`, then start with `pnpm --filter @sim/web start`. Terminate TLS at a reverse proxy and set `DATABASE_URL` only when account storage is wanted. Run `pnpm db:migrate` before starting a database-backed instance. Curated problem data is bundled in `packages/problems`; account data is in PostgreSQL. Set a backup, restore, and retention policy for that database before handling real user data. `pnpm db:prune` deletes expired sessions and rate-limit buckets and should be scheduled by the operator.

Use the included Dockerfile and `docker compose up --build` for the database-free web app locally. `compose.db.yaml` adds optional persistent PostgreSQL storage; its named volume contains account data and must not be treated as disposable while in use. The container exposes port 3000. Do not treat the web container as a sandbox for hostile user code. The Python Docker runner is a separate local CLI image and is not exposed through the web process.

`GET /api/health` is liveness. `GET /api/ready` checks PostgreSQL migration readiness when `DATABASE_URL` is configured and returns 503 if it is unavailable; the container health check calls this route. Run `pnpm verify:full` with Docker and a test PostgreSQL URL before release. Security headers and the current CSP are described in [SECURITY.md](SECURITY.md). This construction branch is not yet declared production ready.
