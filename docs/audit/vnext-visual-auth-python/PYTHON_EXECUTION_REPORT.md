# Python Own Code report

The browser submits editable source and JSON input to a same-origin API. A separately authenticated local service admits a bounded job, creates an isolated Python container, attaches stdin/stdout, collects a bounded trace and removes the container before releasing capacity. The browser polls/cancels using its private job capability.

The player consumes actual execution snapshots and source lines. Integer-array and constrained numeric-graph inference exposes provenance/confidence. Unsupported intent displays variables and raw trace instead of invented algorithm knowledge. Common controls include teaching/technical modes, play/pause, previous/next, seek, speed and reasoning phases. Verified accounts can save, list, load and delete source/input workspaces.

## Dynamic evidence

- Increasing Array input `[8,2,5,1,7]` produces `17`, with four changes ending at `[8,8,8,8,8]`.
- Editing the executed Python return expression to add 10 produces `27`.
- The graph example produces `[0,4,6]` and a graph view.
- A scalar loop produces `30`, variables/raw fallback and an honest unsupported-structure explanation.
- Syntax/runtime/policy/timeout/trace/output/resource errors have bounded codes; cancellation and wrong-capability access are tested.
- Actual container security settings and post-job removal are checked; scheduler tests cover admission, queue limits/deadlines, copied requests and expiration.

The default configuration disables Python. The supported mode is local, loopback and bounded. Public execution, unrestricted Python, C++ and Java are unsupported. See [SECURITY_REPORT](SECURITY_REPORT.md) and [OPEN_GATES](OPEN_GATES.md).
